# Research tasks (action plan items 1, 2 and 7)

These are not code. Their outputs update the specs.

## R1 — First customer and provider (action 1, OD-1)

- Interview 5–8 potential users: individuals building AI apps, platform/architecture leads in organisations, consultants.
- Ask about their current AI workflow, how they design (tools, documents, reviews), how they deploy, and where they lose time.
- Record per interview: role, organisation size, current cloud(s), AI services in use, design artefacts, approval steps, deployment tooling.
- Output: chosen first customer profile and first provider, with reasons; 3–5 representative scenarios (OD-2). Keep sketching scope broad.

## R2 — Discovery questions and inputs (action 2)

- From R1, map the questions an expert asks before designing an AI stack: desired application, existing systems, data location and sensitivity, expected usage (users, requests, documents, tokens), requirements (functional and non-functional), budget and timeline.
- Output: the question bank and input schema in [001](001-guided-discovery/spec.md); each input names which review rule (003) or cost driver (004) consumes it.

## R3 — User testing (action 7)

- Tasks: from a short brief, reach a reviewed design, an estimate and a deployment document.
- Measures: task completion, accuracy of the design against an expert reference, time to completion, estimate error against a priced reference, and whether the canvas adds value over chat plus a separate diagram tool (paired comparison).
- Output: refinements before expanding provider coverage or deployment automation.
