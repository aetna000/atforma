# Implementation and evidence plan

Use the same source of truth for workload prompts, expected behavior and the qualification report. Run real browser/model journeys from empty projects. Archive failures before fixes and repeat affected cases. Keep static design review, runtime emulation, provider schema/mock plans and real account evidence separate.

Start from the seven existing AWS application scenarios plus newly qualified storage foundations on the other clouds. Expand by application contracts, not a count of service icons. Prioritize data intake/replay and AI inference boundaries shared by IoT, observability and maintenance; then authenticated retrieval/chat; then governed external actions for repositories, CRM, cloud operations and security. A provider gets a deployable label only when its complete required application has passed the relevant stages.

Constitution: visible proposals and undo; honest evidence; shared project model; least privilege; coverage maturity labels; no implicit remembered decisions; calm mentor UI; unit, boundary, browser and real-prompt regressions. No public hosting or live non-AWS deployment is implied by this plan.
